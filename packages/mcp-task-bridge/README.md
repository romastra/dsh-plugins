# Мост MCP Tasks

Отдельный Host-плагин для DSH **0.2.2-rc.3 / rc.5**, поддерживающий **legacy MCP Tasks 2025-11-25**. Не заменяет штатный MCP-клиент, не меняет его соединения и не реализует новое расширение `io.modelcontextprotocol/tasks`.

## Использование

1. `mcp_task_tools({})` — настроенные серверы и ограничения, без подключения.
2. `mcp_task_tools({"server":"ssh"})` — разрешённые task-инструменты с точными схемами.
3. `mcp_task_start({"server":"ssh","tool":"ssh_exec_run_streaming","arguments":{"host":"...","command":"...","timeout":60},"max_wait_ms":120000})` — регистрирует фоновую задачу и по умолчанию завершает текущий ход агента. Команда на сервере должна соответствовать запросу пользователя и правилам сервера.
4. Код плагина, не модель, получает уведомления `notifications/tasks/status` и при необходимости опрашивает `tasks/get`. Итоговый результат запрашивается только после terminal-статуса.
5. Штатный `dsh-tool-jobs` отправляет результат в исходную сессию и обычно будит idle-агента. Если его режим `quiet` или лимит пробуждений оставил владельца idle, плагин дополнительно отправляет короткий wake-сигнал только для своей задачи. При штатном пробуждении второй сигнал не отправляется. Для большого результата уведомление предложит один вызов `job_output`.

`completed` означает завершение протокольной MCP-задачи, а не автоматически успешное выполнение команды: для SSH необходимо дополнительно проверить `exit_code` и `timed_out` в результате.

`pause:false` позволяет агенту продолжать независимую работу. `job_list`, `job_output`, `job_kill` работают как обычно. Отмена кооперативная: плагин пытается вызвать `tasks/cancel`, а если это не удалось, сообщает, что удалённая работа могла продолжиться. Статусы failure, isError, обрыв соединения и истечение срока не выдаются за успех. Сбой создания задачи никогда не вызывает автоматический повтор команды.

## Архитектура и границы

- Каждая операция открывает **своё изолированное MCP-соединение**. Нет доступа к приватному соединению штатного DSH MCP-клиента. Нельзя подхватить taskId из другой сессии соединения.
- У каждой фоновой задачи есть владелец: исходный Agent/Session. Результаты и управление защищены штатным JobRegistry. Фоновое ожидание не вызывает модель.
- В профиле должны быть штатные `job_output`/`job_kill` и контроллер задач. Для собственных завершений плагин использует wake-fallback даже при штатном режиме `quiet` или исчерпанном лимите пробуждений; остальные фоновые задачи не затрагиваются. Занятый агент получает штатное сообщение на следующем шаге. Если пользователь прервал агент или его driver завершился ошибкой, дальнейшее автоматическое выполнение не гарантируется.
- **Ожидание не переживает завершение DSH, выгрузку плагина или уничтожение owning Agent.** При остановке выполняется ограниченная по времени попытка отмены; закрытие клиента не является доказательством остановки удалённой работы.
- Максимальное ожидание по умолчанию 24 часа; `max_wait_ms` ограничен Config.maxDurationMs. Тайм-аут самой удалённой команды задаётся отдельно аргументами SSH-инструмента и правилами SSH-сервера.
- В поддерживаемом протоколе taskId и результат хранятся только в пределах lifetime backend. Текущий FastMCP использует память, не Redis: durable restart recovery не реализован.
- Нет elicitation/sampling. `input_required` завершает ожидание ошибкой с попыткой отмены, а не зависает.
- Текст и структурированные данные ограничены Config.resultMaxBytes (64 KiB по умолчанию); обрезка отмечается явно. Изображения, аудио и inline binary не попадают в контекст модели.

## Настройка серверов

В Config.servers задаются имя, транспорт (`stdio` или `streamable-http`), команда/URL, env/headers и **явный allowedTools**. Инструмент обязан объявить optional/required taskSupport, а сервер — Tasks tools/call capability. Аргументы проверяются по исходной JSON Schema до запуска удалённой операции. Для HTTP нужен сервер legacy 2025-11-25, современное расширение не поддерживается. Адреса и credentials управляются конфигурацией профиля; не передавайте секреты в команды.

Пакет поставляется с пустым списком серверов. Для HTTP задайте собственный адрес, порт и путь в `config.servers[].url` в локальной конфигурации профиля (см. [пример](profile.example.yml)). Для `stdio` укажите локальный `command`, `args` и `env`: при использовании SSH/Pageant адреса задаются через `SSH_HOSTS_FILE` или `DSH_SSH_HOST_ENDPOINTS` в `config.servers[].env` так же, как в SSH-бандле. Назначьте узкий явный `allowedTools`. Бандл не копирует состояние других MCP-соединений и не включает серверы автоматически. Не включайте токены в URL и не храните приватные параметры в этом репозитории.

## Проверка и разработка

`pnpm test` / `node --test test/*.test.js` проверяют producer, протокол, отмену, тайм-ауты, ограничения и владельца. Локальная MCP-фикстура не подключается к SSH. Проверка в живом DSH выполняется отдельно: registration → удалённый task → JobRegistry → уведомление агенту; обычные unit-тесты не доказывают пробуждение idle-агента.

Установка и управление — через Plugins; исходники локального bundle связаны с этой директорией. Отключение плагина отменяет текущие ожидания, существующий MCP SSH продолжает работать независимо.
