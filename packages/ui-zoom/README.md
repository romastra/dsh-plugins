# Масштаб интерфейса / Interface zoom

## 1.5.0 — единые координаты всплывающих слоёв

Совместимость теперь обеспечивает сам zoom-плагин, без изменения DSH/ASAR, браузерных прототипов или других плагинов. Координатный стандарт — **viewport CSS pixels**: позиционирующий box имеет эффективный zoom 1; видимое содержимое отдельно сохраняет выбранный зум. Поэтому `getBoundingClientRect`, `offsetWidth/offsetHeight`, `ResizeObserver`, `left/top` и ограничения окна сравниваются в одинаковых единицах.

- Покрыты штатные fixed Menu, submenu, их материал/backing, Tooltip, compact/preview/media HoverCard и его hover-bridge. Невидимые point-якоря меню нормализованы; обычные непортальные absolute-меню не перенастраиваются.
- Меню от штатной кнопки дополнительно привязывается к **самой кнопке** по точной связи `aria-controls`, а не к запомненной копии её экранной позиции. При zoom/reflow/scroll положение пересчитывает нативный CSS Anchor Positioning. Меню по ПКМ без такой кнопки остаётся у viewport-точки нажатия.
- Текст, иконки, ширина/min-width, padding, gap и radius сохраняют масштаб. У меню material и геометрический submenu-anchor не принимаются за текстовые дочерние блоки. Native actions, focus, клавиатура, pinned Tooltip, анимации и правила выбора стороны остаются штатными.
- Существующая компенсация compact-hover в chat-switcher совместима: обе декларации действуют на **тот же box**, не на вложенные дополнительные обёртки. Его индивидуальные привязки Workspace-превью не перезаписываются. Плагин работает и без chat-switcher.
- Адаптер ограничен точными CSS fingerprints поставляемых primitives **DSH 0.2.2-rc.3**, а не всеми `[role=menu]`/fixed-элементами страницы. Неизвестные пользовательские popovers и нативные OS/Electron-поверхности не переписываются. После обновления DSH совместимость необходимо перепроверить.
- Семантическая привязка владеет только отдельным stylesheet и собственным `data-ui-zoom-menu-anchor`; при закрытии/выключении ресурсы снимаются. Значение, изменённое другим владельцем, при очистке не затирается. Нет опроса, RAF-loop, кликов, перехвата native callbacks, переопределения DOM-методов или изменения localStorage ради координат.

`UiZoom.status` дополнительно показывает contract, установку stylesheet, число реальных якорей, конфликты и эффективный zoom обнаруженных слоёв. `count:0`/`measured:0` означает отсутствие открытого слоя, а не успешную проверку его отрисовки. Проверки CSS/алгебры/ресурсов не заменяют проверку экрана на Desktop/телефоне.

**Проверено при установке:** 102/102 теста zoom и 6/6 регрессий совместимого hover-адаптера, финальный source-only UX/technical review без блокеров. Живой Desktop подтвердил 1.5.0, сохранённые 134.9858807576003%, разбор всех 21 CSS-правила, отсутствие ошибок/конфликтов адаптера и эффективный zoom point-якоря 0.99999994 (≈1). Остальные семейства в момент запроса были закрыты; их реальная отрисовка не объявляется проверенной.

## История 1.4.1 — единицы слоя позиционирования

В том же `:root` style-коммите, что и zoom, публикуются `--dsh-ui-zoom-factor` (`z`) и `--dsh-ui-zoom-inverse` (`1/z`). При 100% обе переменные равны 1, но декларация самого zoom не навязывается. Это позволяет адаптеру нативного hover в chat-switcher 1.12.0 оставить positioning layer в экранных единицах и отдельно сохранить увеличенный размер содержимого. Настройка, логарифмическая шкала, локальное хранение и сам регулятор не изменены; существующий post-commit `resize` пересчитывает привязки после изменения процента. ASAR не патчится. Read-only диагностика дополнительно показывает обе переменные.

## Управление

- Одна **лупа** справа в верхней панели чата открывает вертикальный регулятор.
- Дорожка занимает **30% высоты окна**. Круглый рычажок имеет диаметр **7% длины дорожки, но не менее 24px**, чтобы оставаться различимым на телефоне. Область захвата — минимум **48×48px**, включая крайние положения; она шире видимого кружка. Отдельный фиксированный слой компенсирует CSS-зум посредством `zoom: 1/z`, поэтому регулятор не растёт и не уменьшается вместе с UI. При изменении размеров окна геометрия пересчитывается.
- Положение панели фиксируется при открытии: она не «убегает» от указателя при изменении масштаба. Координаты указателя и дорожки берутся в одной системе viewport pixels. Панель остаётся в пределах окна, насколько позволяет его размер.
- Диапазон **50–300%**. Равные шаги по `ln(z)` равны **0.1**: например, 90.5% → 100% → 110.5% → 122.1%. Внутренние значения и сохранение не округляются; подписи округляются до одного десятичного знака.
- **Тянуть нужно контрастный круглый рычажок с небольшим рельефом**. Числа **300%, 100%, 50%** справа — неподвижная шкала: её тонкие деления находятся за пределами области перетаскивания и не похожи на второй рычажок. Широкая светлая чёрточка и залитая зона на дорожке убраны.
- Прилипание к **100%** осталось прежним: к обычному интервалу этого значения добавляется **ещё один стандартный логарифмический шаг с каждой стороны**, только при перетаскивании. При отпускании внутри зоны рычажок становится на позицию 100%. Во время захвата кружок получает мягкую подсветку, а цветной участок дорожки показывает положение.
- Масштаб меняется сразу при перетаскивании; в `localStorage` текущего браузера записывается один итоговый результат при отпускании, потере захвата или закрытии панели.
- **Стрелки** на сфокусированном слайдере — один логарифмический шаг; **Home / End** — 50% / 300%. Кнопка **Сброс** сбрасывает масштаб до 100% и имеет высоту 44px для касания. **Escape**, повторное нажатие лупы или щелчок снаружи закрывают панель. Escape возвращает фокус на лупу.
- **Ctrl + Shift + = / +**, **Ctrl + Shift + -** используют ту же логарифмическую сетку, **без дополнительных пустых нажатий на 100%**. **Ctrl + Shift + 0** — сброс. На macOS используется Cmd. Поддерживается цифровой блок.
- Дополнительные степперы: **Настройки → Общие → Масштаб интерфейса**. Верхняя панель скрыта DSH на пустом стартовом экране; горячие клавиши и настройка остаются доступны.

Локальные дробные значения сохраняются без округления, включая значения вне логарифмической сетки. Первый новый шаг выбирает соседнюю точку сетки в нужном направлении. Обычные сочетания без Shift и настройки размера шрифта чата не меняются. IME, запись горячих клавиш и ввод, уже поглощённый локальным контролом, сохраняют приоритет.

## Хранение и ограничения

Масштаб хранится **только в браузере** под ключом `dsh.ui-zoom.browser.v1` как JSON `{version:1, percent}`. Desktop и телефон используют отдельные хранилища и больше не меняют масштаб друг друга. Host Config, серверные настройки и сетевые вызовы в сохранении не участвуют. Настройка доступна сразу и не ждёт подключения к Host.

Область хранения — браузерный профиль и origin (протокол, адрес, порт). Вкладки одного браузера на одном origin делят настройку через событие `storage`; разные браузеры, устройства и origin независимы. После перезагрузки страницы восстанавливается локальное значение с полной точностью. При смене адреса/порта, очистке данных сайта или новом браузере начальное значение **100%**. Старое общее значение из профиля не импортируется: переход на 1.3.0 один раз начинает со 100% в каждом браузере без локальной записи.

Если браузер запрещает чтение/запись или исчерпана квота, масштаб продолжает работать в памяти текущей вкладки. Уведомление честно сообщает, что значение не сохранено; повторное изменение или сброс повторяет попытку записи. Повреждённая локальная запись не применяется и не перезаписывается автоматически; явное действие пользователя может заменить её.

При перетаскивании промежуточный зум виден только в этой вкладке. Итог при отпускании получают другие вкладки того же origin, но не телефон/другой браузер. Открытые старые страницы нужно обновить для перехода на локальное хранение.

Масштабируется корневой документ, включая порталы в body. Это **CSS zoom, не нативный page zoom Electron**: DSH 0.2.2-rc.3 не предоставляет такого API плагинам. Встроенные нативные поверхности и их ввод не управляются. Штатные всплывающие семейства перечислены в разделе 1.5.0; неизвестные пользовательские поверхности и drag-and-drop требуют собственного корректного координатного контракта. Сам регулятор компенсирует масштаб локально. Исходники DSH и ASAR не патчатся. Отключение плагина удаляет его интерфейс, стили и обработчики, не меняя настройки шрифтов.

Глобальная агентская операция `ui_zoom` удалена: у браузерной настройки нет единственной правильной глобальной цели. Изменение масштаба — локальное действие представления, доступное через лупу, клавиши и степперы. Read-only Client Inspect Provider `UiZoom.status` показывает отвечающую страницу, её локальный масштаб и состояние хранения, но ничего не меняет. Старое поле профиля может оставаться в пользовательской конфигурации и больше не используется.

## Основа визуального решения

- [USWDS — Range slider](https://designsystem.digital.gov/components/range-slider/): различимый подвижный элемент, реакция на захват, подписи пределов и короткая видимая подсказка. Поэтому текущий процент показан сверху, рядом есть «Тяните кружок», а неподвижная шкала вынесена отдельно.
- [W3C — Target Size (Enhanced)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html): большой сенсорный target может быть шире видимого элемента; здесь захват не менее 48px, без такого же увеличения видимого кружка.
- [W3C — Non-text Contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html): существенные визуальные признаки нельзя делать неразличимыми. Кружок отделён формой, непрозрачной заливкой и контрастной границей; одно различие цветов не используется как единственная подсказка. Формальная проверка контраста на всех темах/устройствах не заявляется.

## Development and verification

`node build.mjs` emits the lazy Client artifact. `node --test test/*.test.mjs` checks logarithmic arithmetic, the sticky plateau, keyboard traversal, viewport geometry, preview/commit persistence, separate Desktop/phone storage backends, reloads, same-origin tabs, stale storage events, permissions/quota failures, recovery, disposal, viewport-unit algebra, submenu/page/width-matching variants, version fingerprints, semantic anchor escaping, lease ownership and resource integrity. React is supplied by DSH; there are no install scripts or external network requests.

Live registration is checked after installation. No authenticated browser-control tool is available in this session, so rendered light/dark appearance, real pointer capture and on-screen size invariance need confirmation in the connected page. Tests of arithmetic and registration alone are not a visual check. The inventory icon is original SVG; an optional feature image is intentionally omitted.
