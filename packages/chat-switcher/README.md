Локальный плагин `@local/chat-switcher` **1.16.1** для локального DSH (финальная проверка — 0.2.2-rc.5). Установленное приложение и его ASAR не изменялись, другой сервер не запускался. Подтверждённого `dev:web` watcher нет. Версию применяет штатный менеджер плагинов; простая пересборка исходников сама по себе не гарантирует обновление открытого окна. Экспорт Client указывает на versioned artifact из manifest, сборщик пишет именно его; прежний `client.js` оставлен неизменным и не входит в экспорт/пакет.

## Изменение 1.16.1 — отступы поля ввода по фактическому переносу

- `margin-bottom: 14px` у редактора включается со второй реально отрисованной строки, в том числе при переносе одной распорки или явном переводе строки. Фокус, непустой однострочный ввод и минимальная высота пустого hero-композера не включают отступ. Размер вычисляется по блокам абзацев с учётом `::after`, независимо от высоты панели и её аксессуаров.
- `margin-bottom: 47px` у нативного scrollport включается отдельно, когда его содержимое действительно прокручивается по вертикали и полоса не отключена стилем. При сокращении текста оба отступа снимаются по своим условиям; временное системное автоскрытие полосы на отступ не влияет.
- Измерения принадлежат существующему слоту композера; короткоживущие флаги выставляются только на его `<style>`. Черновик, caret BR, распорка, Send/Stop и открытые меню не переписываются. Наблюдатели отключаются при снятии слота. Диагностика `ChatSwitcher.status` показывает только размеры и отступы без содержимого черновика.

Сборка, синтаксис и **703/703** теста chat-switcher и уведомлений прошли. Сравнение с эталонным CSS подтверждает, что изменились только два правила отступов. Артефакт 1.16.0 и генератор Worker сохранены побайтово. Независимое ревью по коду завершено; 1.16.1 применена менеджером, новый слот в живом Client активен. Интерактивный ввод для проверки переноса и scrollbar не выполнялся.

## Изменение 1.16.0 — наличие фрактала как параметр

У новых явно выбранных изображений (`hybrid-fractal/v2`) есть отдельный raw boolean `getFractalParameters(seed).enabled`. Его бит определяется солью в независимом RNG domain, не изменяя прочие draw-последовательности. Без отбора 400 salts дали 209 ON / 191 OFF. Сохранённые legacy и V1 остаются прежними: V1 domain/11 controls/картинки не менялись, сравнение со shipped 1.15.1 прошло на 48 V1 seeds, прежние 276 legacy digest-кейсов сохранены.

**С прежним all-parameters правилом присутствие обязательно меняется при каждом нажатии:** legacy OFF→новый ON; V1 ON→новый OFF; далее V2 ON/OFF чередуются. Все 19 базовых входов и общие позиции палитры всё так же отличаются. 11 фрактальных controls сравниваются лишь когда фрактал активен на обеих сторонах; неактивные поля OFF не являются параметрами видимого рисунка. Иначе два бинарных обязательных переключения presence/family навсегда закрепили бы одно семейство за всеми ON-картинками. Проверенная серия из 36 reroll сохраняет чередование и допускает обе Julia/Mandelbrot на ON.

OFF синхронно выдаёт точный plain SVG той же геометрии/палитры: **без quality probe, полного фрактального поля, cooperative job или создания Worker**. ON использует прежний bounded async renderer. Отдельный `hasMosaicFractal(seed)` управляет art-store по реальному presence, а не по одному имени generation. Storage schema допускает обе V1/V2, отсутствующий variant остаётся legacy; до явного нажатия сохранённые salt/revision/variant не переписываются. CAS учитывает variant.

**786/786** тестов chat-switcher/уведомлений прошли после fresh versioned build, включая точный URI Worker↔основной renderer для V2 ON и OFF, переключение legacy/V1/V2, отсутствие вычислений OFF, обе ON-семьи и старый byte parity. Source-only UX/technical review принят. Новое поле Inspect `fractalPresence:seed-parameter-toggle`. Финальное применение менеджером applied без warnings; Desktop подтвердил 1.16.0/ready, новый presence marker, готовый art-store без pending/fallback jobs и прежние геометрию composer/переходы. Host readonly get подтвердил policy v3; текущие salt/revision/legacy variant до/после обновления совпали. Физическое изменение текущей картинки агентом для теста не выполнялось.

## История 1.15.1 — гибрид: фрактал внутри крупных фигур

При **следующей явной смене картинки** сохраняется вариант `hybrid-fractal/v1`: крупные исходные многоугольники, контуры, ownership masks, симметрия и палитра остаются основой; внутри до двух наиболее крупных орбит фигур появляется заливка Жюлиа/Мандельброта. Inset 0.88–0.94 оставляет цветной ободок. Локальные D_m-симметрии и зеркальные/повёрнутые копии используют один и тот же канонический фрагмент, без разного шума у симметричных объектов.

### Совместимость и отбор

Старые записи без variant и новые чаты при ensure по-прежнему используют прежний seed и renderer. В storage добавлено только optional variant, без переписывания старых salt/revision. `identitySeed` для legacy побайтово прежний; только hybrid использует отдельный domain marker. **276 прежних scene/SVG сверены по pre-change digest без отличий.** Цвета берутся только из текущей выбранной C64-палитры, новых цветов не добавляется.

При reroll по-прежнему меняются все 19 базовых входов и общие позиции палитры; между двумя hybrid дополнительно меняются все 11 raw fractal-входов: family, centerReal/Imag, windowSpan, juliaReal/Imag, fieldRotation, bandDensity/Phase, rimScale, paletteOffset. Затем идут дешёвый palette contrast≥3 и четыре probe 24×24×64 по симметриям 0/1/3/6. Отсеиваются одноцветные/плоские фрагменты, но это **эвристика**, не доказательство деталей после всех clip конкретного полигона. Семейство Жюлиа/Мандельброт чередуется при повторном hybrid-reroll из-за строгого all-parameters правила. CAS проверяет также variant из отрисованного snapshot.

### Жёсткий бюджет и UI

- Float64, конечный набор ограниченных окон, поле **64×64**, максимум **96** итераций на точку, ранний escape. Полный renderer строит не более двух полей: ≤786 432 complex steps; acceptance probe отдельно ≤147 456. Без deep zoom/произвольной точности.
- SVG содержит общие path definitions и `<use>`, а не тысячи копий фрактала; row-run serialization ограничена и при необходимости упрощается с 64 до 32. Сохраняется выбранная палитра; форма/маски не изменяются.
- React никогда синхронно не строит полный fractal. Один lazy Worker на среду обрабатывает очередь последовательно. Worker source автоматически собран из **того же** pure renderer. При запрете Worker/CSP — cooperative fallback с yield каждые 4 строки (≤24 576 шагов между yield).
- Изначально показана дешёвая базовая мозаика того же seed; полный URI приходит в общий external store и обновляет кнопку, модальные/hover-превью и свайп-кружки. Фон ждёт полный URI и затем использует прежний native raster512 pipeline. Сам рисунок не превращается в маленькую PNG при увеличении перехода.
- 32 idle LRU entries, ≤64 queued/active jobs; лишние mounted записи **ждут свободного слота**, а не получают вечный fallback. Отдельной неограниченной очереди нет. Снятие последнего потребителя, needed=false и unload отменяют работу; Worker, BlobURL, watchdogs/yield/poll timers освобождаются. Окончательный render failure оставляет base с понятным tooltip и возможностью повторной смены.

В изолированном benchmark 80 accepted hybrid seed: все прошли probe, средний поиск 9.26 кандидата / 4.04ms; full SVG в среднем 3.62ms, максимум 12.96ms; максимальный SVG 73 390 байт. Это Node CPU-измерения, **не гарантия paint/времени на телефоне**. **771/771** тестов chat-switcher/уведомлений прошли после финальной сборки. Матрица включает legacy digests, sync/async/Worker byte parity, local symmetry, strict reroll, optional variant/reopen/CAS, store cancellation/late callbacks, очередь из 70 mounted seeds и package dependencies. Независимый source-only UX/math review принят; промежуточная 1.15.0 заменена отдельным final artifact URL 1.15.1 для исключения раннего Client-cache. Физическое нажатие и смена существующей картинки агентом для проверки не выполнялись. Финальное применение штатным менеджером: applied, без warnings. Live Client подтвердил **1.15.1/ready**, hybridMode=on-explicit-reroll, прежние compositor dimensions/clip и zoom transitions; до пользовательского reroll нет active/pending/fallback hybrid jobs. Read-only Host get подтвердил hybrid policy v2; текущие salt, revision и legacy variant **до/после применения совпали**. Это подтверждает загрузку/совместимость, не физический paint нового фрактала на устройстве.

## История 1.14.1 — смена соли до изменения всех параметров

При явной смене картинки Host перебирает соли, пока **каждый из 19 изменяемых входных параметров** не отличается от предыдущего: axes, colors, polygonCount, palette, rotation и 14 controls (cellMix, paperRadius, chamfer, gap, radialExponent, contourOffset, contourTurnActivity, contourExponent, powerVariation, composition, seamPixels, convexity, centralInnerRatio, occupancyRadius). Палитра проверяется ещё строже: ни один цвет в совпадающей позиции не повторяется, включая canvas palette[0]. Непересечение множеств цветов не требуется (в полной C64-палитре это невозможно).

Сравниваются реальные входы того же детерминированного генератора, не отличие seed/hash или случайная оценка картинки. Константы/version, seed ID/hash, производные SVG-координаты и принудительные renderer-overrides не считаются независимыми изменяемыми настройками. В частности, seamPixels здесь — raw control; renderer по своим прежним условиям может принудительно включать seam. Сам генератор/RNG/рисунок по старой соли **не менялись**: независимая проверка 276 seed дала точное совпадение старых scene/SVG/data URI.

Rejected-кандидаты не строят scene/SVG, не заполняют image/raster cache, не записываются и не мигают в интерфейсе. Сохраняется только один accepted salt, после durable commit обновляются все текущие consumers. Новые чаты при первичной ensure получают соль как прежде; уже сохранённые картинки до нажатия остаются прежними. Tool chat_image использует тот же Host-путь; read-only get сообщает regenerationPolicy.

Кнопка передаёт соль из своего отрисованного snapshot + generation. Stale/concurrent reference отклоняется до поиска вместо незаметного сравнения с другой картинкой; per-session очередь и один revision/notification сохраняются. HTTP abort, закрытие чата и unload останавливают поиск; busy/error остаются штатными. Подбор идёт batch32 с уступкой Host event loop, до 4096 попыток как защита от сломанного источника случайности. При исчерпании/сбое **нет ослабления условия**: прежняя картинка сохраняется с ошибкой, а не принимается частично похожий кандидат.

**Проверка:** сборка/синтаксис и **711/711** тестов chat-switcher/уведомлений прошли. В изолированном benchmark без изменения чатов: 100 подборов, среднее 8.01 кандидата / 2.39ms, максимум 32 кандидата / 11.98ms (не runtime SLA). Покрыты все поля/позиции палитры, legacy/salted reference, повторные/невалидные UUID, limit/yield/abort, сериализация/CAS, единичная запись, storage failure, package dependencies и неизменность старого арта. Workspace tint, composer, Send/Stop, тексты/черновики, сортировка и переходы не меняются. Независимый source-only UX/technical review принят после объединения строгого RFC UUID validator для ensure/chooser. Применение штатным менеджером: applied, warnings пусты; реальный Desktop подтвердил Client 1.14.1/ready, прежние Workspace tint/zoom transitions/composer appearance. Read-only chat_image get подтвердил новую Host regenerationPolicy; salt и revision текущего чата **до/после обновления совпали**. Первый Client-запрос попал в короткий registration gap после reload, последующий подтвердил ready. Физическое нажатие/изменение реальной картинки агентом для теста не выполнялось.

## История 1.13.0 — zoom выбранной картинки к центру чата

Тап/клик по карточке в модальном переключателе теперь запускает тот же переход увеличения и затухания, что завершение свайпа. Для **обоих кружков и карточек** центр изображения за 280ms с `ease-out` смещается в центр реальной области чата, а не остаётся в исходной точке. Переход не задерживает штатное открытие выбранной сессии.

- Снимок берётся до закрытия модалки только со своего preview/img и собственного grid. В transient layer копируется изображение, а не название чата, TODO/Goal или произвольный DOM. Карточка сохраняет реальные пропорции, radius, object-fit:contain и исходный шейдер/opaque letterbox; круг сохраняет свой glyph.
- Целевая область — detached snapshot существующего owned chat-area tracker до навигации. Дельта переведена в CSS-единицы слоя; `translate(...) scale(...)` увеличивает картинку без увеличения самого смещения. Масштаб рассчитывается относительно конечного центра и покрывает viewport. Без известного chat-area используется центр viewport.
- Частично прокрученная карточка начинает с видимого crop, который раскрывается во время приближения; полностью невидимый preview не создаёт ложный zoom. Визуальная ошибка/недоступная геометрия не блокирует выбор.
- Выбор клавиатурой в **уже видимой** модалке также снимается до clear/unmount. Короткий Ctrl+Tab без показа окна по-прежнему мгновенный. Frozen-приоритеты, проверка актуальной доступности/архива, отсутствие двойного открытия от queued click сохранены.
- Reduced-motion — только короткое затухание без движения/увеличения/раскрытия crop. Layer pointer-inert, выше native dialog через popover при поддержке; blur/hidden/новый keyboard cycle/teardown снимают owned анимацию, RAF и timeout.

**Проверка:** сборка/синтаксис, **654/654** теста chat-switcher/уведомлений прошли. Геометрические проверки включают fractional zoom, portrait/landscape/offset viewport, конечный центр, viewport coverage, aspect, crop, reduced motion и cleanup; интеграционные — capture-before-clear, native navigation, source image, исчезнувшую/архивную цель, duplicated click и fallback. Source-only UX review не заменяет физическую оценку плавности на подключённой странице. Composer/Send и исправление координат ui-zoom не менялись. После применения Desktop подтвердил `version:1.13.0`, `formStatus:ready`, `releaseTransition:zoom-to-chat-center-ease-out-280ms`, `selectionTransition:modal-preview-same-animation` и доступный собственный modalArea. Computed composer clip/размеры/форма кнопки остались прежними. Физическое движение/ощущение easing проверяется пользователем в текущем GUI.

## История 1.12.6 — composer/Send по выверенному референсу без отдельного fixer

Пользовательский референс — `chat-switcher-backups/before-bidirectional-menu-1.10.4-client.js`. Чистые CSS composer/backdrop и генератор мозаики уже совпадали с ним; отдельный attachment-menu-fix постоянно перекрывал card overflow, радиус кнопки и max-height. Оформление базы **не переписано**: exact string parity с референсом проверяется для source и generated Client на обычных/солёных/unicode ключах.

Теперь совместимость меню — часть владельца оформления: `composerMenuVisibilityCss` в том же style-seat. Только пока внутри существует native MenuView (`data-trigger-menu`) либо native PopupSelect search (/model, /permission, включая pending) снято clipping и сохранён прежний временный corner/height fallback. ## История 1.12.4 — Goal при отсутствии списка TODO

Goal входит в штатные summary keys, поэтому совместимый холодный header checkpoint также появляется в canonical projection cache без чтения логов. Если checkpoint отсутствует/несовместим или goal неизвестен, надпись скрыта — history/retain/backfill не добавлены. Последующее sequenced обновление и null поступают через имеющийся native stream.

## История 1.12.1 — максимально крупный TODO-текст

Каждая модальная карточка подбирает собственный **наибольший помещающийся шрифт**. Для задачи отдана вся свободная область изображения над нижними статусами, а не прежние 48% и три строки. Короткий текст увеличивается, длинный переносится и уменьшается; центрирование, полупрозрачный фон и межстрочный интервал 1.12 сохраняют читаемость. RAF, ResizeObserver и listeners очищаются при снятии карточки.

Если даже минимальный размер не помещается (например, ограничения браузера на минимальный шрифт), полный текст не отбрасывается: включается собственная прокрутка с клавиатурным фокусом. ## История 1.10.1 — размер, визуальное натяжение и приоритеты

**Размер:** native dialog занимает ровно 90% ширины и высоты основной области чата, с полями 5% от её сторон, а не от всего окна. Собственная невидимая область в HOC измеряется `ResizeObserver`; боковые панели, окно, visual viewport и CSS zoom учитываются. Embedded rightbar исключён по native marker. Верхняя строка остаётся на месте, прокручивается сетка превью. Native showModal/focus/Escape сохранены.

**Натяжение:** никаких надписей поверх чата или модалки. У края появляется эластичная мембрана с заполняющейся дугой. Кружок увеличен с радиуса 19 до 27 CSS px; открытие обозначено оригинальным глифом окна с четырьмя мини-карточками, закрытие — общей с превью уникальной мозаикой фактически открытого чата. Картинка не зеркалится. Мембрана растягивается на 32% края, но отдельный SVG головы оставляет круг круглым. Движение непосредственно зависит от пальца, без бесконечного spinner/автономной анимации. Принцип прогресса, сопротивления и порога адаптирован из [Material swipe to refresh](https://m1.material.io/patterns/swipe-to-refresh.html); это не загрузка данных и чужая графика не копировалась.

**Порядок:** 0 — текущий основной чат (даже idle); 1 — доступ/вопрос/проверка плана; 2 — ошибка; 3 — подтверждённое успешное завершение; 4 — закреплённые, работающие, остальные допустимые уведомления и посещённые за последние 60 минут чаты. В группах 1–3 более раннее наблюдаемое событие выше; в группе 4 сохранён прежний MRU. Короткий Ctrl+Tab выбирает первый чат после текущего. Пока окно/цикл открыты, порядок заморожен: меняющиеся события могут убрать невалидную карточку, но не перемещают остальные.

**Последний час:** записываются только реальные входы и выходы из чата, не status rerender. Чат, в котором оставались долго, получает свежую отметку при выходе. Незакреплённый неактивный чат ровно через час исчезает, если не стал текущим/работающим/требующим внимания; для этого есть один таймер ближайшего истечения, без нового polling. Отметки хранятся отдельно от старого MRU, в localStorage текущего browser-origin, максимум 1000. При недоступном storage работает память. Архивы, отсутствующие строки и субагенты не включаются даже при недавнем визите.

**Честные ограничения времени:** прежний attention bridge не публикует timestamp/event id и перестраивает строки при посторонних обновлениях. Поэтому сохраняется firstObserved непрерывного события, а не возраст объекта. Старые события, впервые увиденные одновременно после обновления, имеют неизвестную историческую очередность и tie по MRU. Смена одного события на другое того же типа без gap/id неразличима. Для живых запросов учитывается callId/key; для будущего расширенного bridge поддержаны eventId/occurredAt/receivedAt, но текущему источнику они не приписываются. `completionUnread` сам по себе не называется успехом. Старые MRU-идентификаторы без дат не превращаются автоматически в визиты «за последний час».

**Проверка:** 473 unit/regression-теста, сборка и синтаксис прошли, включая соседние звуковые оповещения. Независимый source-only UX review пройден. Визуальное натяжение предыдущей итерации пользователь одобрил. Версия 1.10.1, подключение и успешные открытия/закрытия подтверждены live Inspect на телефоне. Открытый dialog не удалось зафиксировать одновременно с измерением: к моменту ответа страницы он уже был закрыт, поэтому точное browser-подтверждение полей 5% и финальная визуальная оценка не заявляются. Автоматического управления браузером или screenshot-renderer не использовалось. Звуковые настройки и бюджеты не изменялись.

## Изменение 1.7.0 — акцентная палитра активного чата

Весь интерфейс наследует акцентную палитру рисунка **фактически открытого** чата. Выделение в Ctrl+Tab-превью до перехода её не меняет. Кнопка-палитра меняет рисунок и соответствующие акценты; переключение светлой/тёмной/системной темы пересчитывает цвета по текущему CSS. Ошибки, предупреждения, успех и нейтральные поверхности не перекрашиваются: слой меняет только `--dsw-static-deepseek-*`, а штатные семантические алиасы пересчитываются на `body`. Остальные цветовые семейства остаются штатными. Флажок в настройках по-прежнему управляет только Ctrl+Tab.

### Алгоритм и владение

- Имена, число ступеней и исходные цвета читаются из `getComputedStyle(document.body)` по prefix во время работы. Таблица оттенков/HEX в коде не зашита. На время чтения синхронно отключается только собственный React-owned stylesheet; computed строки копируются и probe-нормализация завершается до его восстановления в `finally`.
- Чистая OKLCH-математика: chroma-взвешенный circular mean, общий кратчайший поворот H с сохранением индивидуальных hue offsets; насыщенность — отношение `C/Cmax(Y,h)` с ограниченным мультипликативным усилением. Для серого рисунка получается нейтральный ряд.
- Для каждого исходного цвета численно подбирается L с сохранением его WCAG relative luminance Y. Если цвет не помещается в sRGB, уменьшается C, а не обрезаются RGB-каналы. Результат сериализуется с высокой точностью и повторно проверяется; alpha не меняется.
- Один невидимый root-slot компонент владеет глобальным стилем и probe. Нет прямых записей в чужой DOM, смены theme preference или собственных `theme/change`. Native события объединяются в microtask после полного синхронного presenter dispatch; локальный layout-state обновляет стиль до первого paint. Поиск чатов, рисунков и состояния использует уже существующие metadata stores, без чтения истории/драфта и без нового polling.
- LRU ограничен 32 производными палитрами и ключуется исходной палитрой + цветом рисунка. A→B→A не накапливает преобразования. При отсутствии чата, отключении bundle или неподдерживаемом цвете слой удаляется: только штатные цвета, без частично перекрашенной палитры. Ошибка палитры даёт отдельную локализованную подсказку, не выдаётся за ошибку сохранения рисунка.

Сохранение Y сохраняет исходный WCAG-контраст **непрозрачных** цветов с неизменным фоном и между собой, но не исправляет изначально недостаточный контраст. `color-mix()`, прозрачность, blend и текст на неоднородном рисунке требуют отдельной визуальной проверки; гарантия для таких комбинаций не заявляется.

### Проверка и резервная копия

Проверены roundtrips, sRGB gamut, сериализованная Y, 11 исходных оттенков × 77 целей, попарный непрозрачный контраст и seeded fuzz; runtime-проверки покрывают baseline без своего слоя, смену темы, A→B→A, точный case-sensitive prefix, all-or-native fallback, coalesced invalidation и cleanup. Пройдён независимый UI/UX review по исходникам; visual/browser control недоступен, поэтому реальная читаемость всех состояний интерфейса и отсутствие flicker визуально не подтверждены.

Финальная проверка: сборка standalone client, синтаксис, metadata/locale и **249/249 unit-тестов** прошли. Штатный менеджер применил 1.7.0 (`application: applied`, без application warnings); текущий Client подтвердил активные `chat-switcher:body-palette:1.7.0` в `shell.overlay` и `chat-switcher:image-style:1.7.0` в `conversation.input.overlay`. ## Поведение

- Короткое Ctrl+Tab, затем отпускание Ctrl: самый приоритетный чат после текущего. Если горячих событий нет, сохраняется обычное MRU-переключение.
- После первого Ctrl+Tab при удерживаемом Ctrl через **250 мс** появляется окно. Задержка 0–2000 мс меняется в **Настройки → Общие → Переключение чатов**, а также на странице плагина; изменения применяются после «Сохранить».
- Пока Ctrl удерживается, Tab двигает рамку вперёд, Shift+Tab — назад. Отпускание последнего удерживаемого Ctrl открывает выбранный чат. Enter — резервное явное подтверждение, Esc — отмена. Потеря фокуса окна/скрытие приложения отменяет незавершённый выбор.
- Порядок — текущий чат, запросы/вопросы, ошибки, подтверждённая готовая работа, затем остальные по MRU. В событийных группах более раннее наблюдаемое событие выше. Порядок фиксируется на весь цикл выбора: новые сообщения и оповещения не двигают карточки.
- Только основные чаты: дочерние сессии, отсутствующие и архивные строки исключены. Включены текущий, закреплённые, работающие, требующие внимания основные чаты и подтверждённые визиты за последний час. Старое MRU без времени визита или само наличие строки в каталоге не добавляют остальные idle-чаты.
- Заголовок полный, без многоточия и ограничения строк. Большой список прокручивается; выбранная карточка автоматически становится видимой.
- Клик по карточке сразу открывает её; навигация сама по себе не подтверждает внимание и не отвечает на запросы.

MRU хранит только идентификаторы чатов в локальном хранилище окна и сортирует уже отобранных кандидатов. Исторические посещения до установки восстановить нельзя: ещё не посещённые идут в порядке закрепления, затем каталога. Если хранилище недоступно, порядок сохраняется в памяти до закрытия страницы. Отдельные окна имеют независимый текущий цикл; это не серверная общая история посещений.

## Превью и нагрузка

Первая версия намеренно использует **информационную карточку**: папка проекта, работа/ожидание, тип запроса внимания и состояние оповещения. Скриншотов, фоновой отрисовки переписки, отдельных retain/open для каждого чата и дополнительных запросов истории нет. Используются уже опубликованные каталоги и статусы DSH; таймер один, только на появление окна.

Фрагмент последнего сообщения можно добавить позже отдельным режимом: короткий текст с ограниченным кэшем и чтением только видимых карточек. Сейчас его нет: список DSH не содержит готового last-message preview, а чтение истории для каждой карточки увеличивает нагрузку и требует корректно учитывать редактирование/замены сообщений. Визуальные скриншоты тяжелее и могут показывать устаревший текст.

## Отметки внимания

Карточки и боковой список показывают:

- **●** — неподтверждённое внимание: доступ, вопрос, проверка плана или остановка, требующая внимания;
- **♬** — у этого события ещё есть активная/очередная последовательность оповещений, включая длинную паузу между сериями;
- **✓** — доставленное успешное завершение.

Срочность выделяется цветом **и подписью**, но не меняет MRU-порядок. Незакреплённые чаты с активностью или вниманием участвуют в переключении наравне с закреплёнными. После снятия последнего признака внимания/работы незакреплённый чат исключается.

Нужен обновлённый локальный плагин [звуковых оповещений](<sound-notifications/README.md#L15-L23>): добавлен read-only мост состояния. Выключенный звук, блокировка autoplay и исчерпанные повторы не стирают доставленную отметку внимания. Значок активного оповещения **не доказывает слышимость**: системный/вкладочный mute не наблюдается. Если Host не передал событие из-за своих настроек, восстановить его по истории мост не пытается. Нет моста — переключение работает, но предупреждает о недоступности звукового состояния.

Открытие/перелистывание карточек, Ctrl/Tab/Shift и их сочетания не гасят оповещение. Настоящее действие внутри выбранного чата подтверждает внимание по прежним правилам звукового плагина. Его настройки и пользовательские звуки сохранены.

## Изменение 1.5.1 — растровый фон и очистка ресурсов

По подтверждённому выбору пользователя растровым сделан только фон области чата. Для него исходная общая SVG один раз рисуется в PNG 512×512 без потерь; лёгкая SVG-обёртка содержит лишь сплошную заливку и image с PNG, без сложных polygon/mask/filter. При изменении размеров браузер масштабирует готовый растр, а не повторяет фильтры мозаики в размере окна. На больших экранах границы фона могут быть мягче; это выбранный компромисс качества. Кнопка, Ctrl+Tab и hover Workspaces остаются исходными векторными SVG. Цвет до краёв, отступы 10%, contain и тематический слой 85% сохранены.

Кэш растровых ресурсов — LRU 16 записей плюс ресурсы реально открытых редакторов. Подготовка ленивая, только для смонтированных потребителей. Одновременно выполняется одно задание; ненужные задания удаляются из очереди, а после завершения decode проверяется видимость до drawImage/PNG encoding. Активные/ожидающие сессии дедуплицируются и при вытеснении из LRU. Canvas освобождается после кодирования. Поздний результат не перекрашивает новый чат. При ошибке сохраняется безопасный векторный fallback; следующее монтирование может повторить попытку. Первому кадру до готовности PNG доступна точная фоновая заливка без дорогостоящей векторной геометрии.

Пройдены 94 unit-теста, включая быстрое переключение более 16 сессий, отмену очереди и повтор после ошибки; Chromium smoke подтвердил настоящий PNG 512×512 внутри фонового SVG, отсутствие в нём сложных фильтров, сохранение цвета и layout в четырёх пропорциях и двух темах. Отдельно проверены прежняя SVG-кнопка Send/Stop и незатенённый hover. Это изолированные проверки собранного клиента, не численный FPS-бенчмарк текущего Desktop.

## Изменение 1.4.2 — переиспользование SVG без изменения оформления

Основной алгоритм уже генерирует SVG один раз при промахе общего LRU-кэша (128 URI на окно/экземпляр плагина). Кнопка, модальная карточка и hover Workspaces используют одинаковый data URI. Фон получает геометрию из этой готовой SVG, не запуская алгоритм повторно, но требует отдельного SVG-документа-обёртки для растягиваемой заливки и contain-отступов. Браузер может отдельно декодировать/растеризовать документы и размеры — это не новый прогон генератора.

Добавлен небольшой LRU-кэш 16 готовых фоновых обёрток: повторное монтирование/открытие редактора не декодирует исходный URI и не пересобирает/кодирует обёртку заново. Записи заморожены; в кэшах нет сцен, историй и объектов сессий. При вытеснении фоновой обёртки общий SVG может оставаться в кэше; пересобирается только обёртка. После перезагрузки или вытеснения базовой SVG генерация допускается снова.

Геометрия, SVG-байты, цвета, opacity, размеры и CSS оформления не менялись. Инструментированный тест подтвердил один прогон алгоритма и одну подготовку обёртки для многократных обращений всех потребителей к одному чату. Пройдены 87 unit-тестов, проверки предела/вытеснения кэша, побайтное сравнение с прежней подготовкой и Chromium pixel smoke в четырёх пропорциях. ## Изменение 1.4.0 — фон чата

На неподвижную область `[data-conversation-content]` ниже заголовка нанесён фон своей сессии. Фоновый цвет берётся из полного canvas-прямоугольника того же SVG, а не угадывается по палитре. Внешний SVG растягивает только эту заливку до всех краёв; вложенная исходная мозаика вписывается без искажений в центральную область с отступами не менее 10% (contain, без обрезки). Геометрия и изображение чата не меняются.

Сверху наложен текущий `--dsw-alias-bg-base` с непрозрачностью 85%: видимый цвет = 15% изображения + 85% тематического фона. Переключение темы применяется сразу. Непрозрачность сообщений и кнопок не меняется. Родная непрозрачная градиентная подложка sticky composer-seat убрана, чтобы не накладывать второе затемнение; собственная поверхность редактора, сообщения-карточки, код и остальные смысловые поверхности сохраняются. Изображение центрируется относительно видимой области чата, не прокручивается вместе с историей и не меняет layout. Непрозрачные альтернативные вкладки, например Trajectory, сохраняют своё оформление.

Стиль декларативно привязан к сессии редактора через существующий компонент; вложенные области с другими сессиями не перекрашиваются. Без привязанного редактора остаётся нативный фон. ASAR и глобальные переменные темы не менялись. Пройдены 84 unit-теста, Chromium-проверки светлой/тёмной темы и четырёх пропорций области, а также сравнение пикселей с эталонным inline SVG: точность фонового цвета, 85% тематического слоя и contain-геометрии. Проверки выполнены на изолированном стенде собранного клиента, не в текущем окне Desktop.

## Изменение 1.3.0 — изображение чата на кнопке отправки/остановки

Размер — 156,25% исходной кнопки (два последовательных увеличения на 25%); в текущем DSH 34 px → 53,125 px. Скругление — 33%. При наведении, отправке и disabled изображение остаётся чистым. Доступное название, tooltip, фокус, disabled, отправка/steer/queue и остановка остаются нативными. При наличии дополнительной кнопки прерывания она не изменяется.

Оформление подключается через session-scoped `conversation.input.overlay` и локальный style, не заменяя кнопку и не назначая обработчиков. Каждый редактор получает изображение своей сессии; при смене сессии/размонтировании стиль автоматически заменяется/снимается. Без сессии действует родное оформление.
