# Сохранение черновиков / Draft preservation

Локальное исправление для установленного DSH Desktop **0.2.2-rc.3**. Не изменяет архив приложения, сессии, глобальный режим по умолчанию или штатные элементы интерфейса.

## Что сохраняется

При переходе из нового чата в другой и возврате через «Новый чат»/рабочую папку сохраняются исходный выбранный режим, вставленные из буфера картинки и добавленные файлы. Сохраняются сами объекты вложений, их порядок, previews и существующие загрузки, без повторной вставки и дублирования. То же удержание защищает вложения обычных чатов. Текст, цитаты и встроенные ссылки продолжает сохранять штатный редактор.

После успешной отправки или удаления вложения не появляются снова. Ошибка отправки оставляет черновик для повторной попытки. При отправке и уходе до ответа Host исходная сессия удерживается до завершения попытки. Если текст очищен вне экрана, актуальное состояние удерживается до штатного сохранения при возвращении — уже отправленный текст не восстанавливается из старого storage.

## Ограничения

- Вложения сохраняются **только при навигации в текущем окне**. Перезагрузка страницы, закрытие Desktop, выгрузка/отключение расширения освобождают объекты браузера. Это не долговременное хранение и не резервная копия.
- Уже потерянные вложения восстановить невозможно.
- Режим сохраняется для существующего пустого чата с Session ID. Предварительный выбор режима на экране без выбранной рабочей папки/сессии этим исправлением не меняется.
- Если сохранённый режим удалён или не может активироваться, сохраняется штатный переход к режиму по умолчанию. Другие ошибки и явно запрошенный режим не подменяются.
- Архивирование/удаление сессии освобождает её временное удержание. Удержание файла в памяти само по себе не запускает агента, не отправляет сообщения и не подтверждает уведомления.
- Исправление привязано к указанной версии DSH: после обновления следует проверить совместимость, а не выдавать исключение версии без анализа.

## Устройство

`src/preservation.js` — отдельно тестируемая логика. Один дополнительный `SessionReference` сохраняет точный Session binding, пока есть вложения, незавершённая отправка или ожидающее сохранения изменение текста. Источник references — отдельная метка `draftPreservation`, не `mainView`. Штатный input, редактор, upload queue, preview и сериализаторы остаются единственными владельцами данных.

Наблюдатель устанавливается через `uiSession.provide` с дедупликацией по binding. Он не монтирует скрытый composer, не перехватывает буфер обмена, не читает DOM и не копирует содержимое файлов. Невидимая запись штатного composer overlay подтверждает повторный mount и вызывает штатный `inputActions.persistDraft`.

Для режима используется узкая обратимая обёртка `sessions.create`: только при повторном открытии named blank без явно переданного режима подставляется его текущий `agentPreset` из live projection или списка сессий. Все остальные параметры, receiver и результат сохраняются. На отключении восстанавливается исходный descriptor; более поздние сторонние обёртки не удаляются.

Read-only Inspect provider `DraftPreservation.status` публикует только версию и агрегированные счётчики, без текста черновиков, имён файлов или их содержимого.

## Проверки и сборка

```text
node --test test/*.test.mjs
node build.mjs
node --check client.js
```

`build.mjs` объединяет проверенный исходник с browser entry в обычный ModuleLoader artifact; зависимостей для сборки нет. Установка локальной папки выполняется штатным Plugin Manager. При изменении исходников запускайте сборку явно — dev-web watcher в установленном Desktop не используется.

Автотесты проверяют отдельные Session generations, оригинальные File/ID и порядок, отсутствие утечек между чатами, удаление, все фазы отправки, ошибки, очистку и сохранение вне экрана, повторный mount, гонки release/retain, архивирование и отказ/выгрузку. Проверка настоящего Ctrl+V и переходов в открытом Desktop требует ручного прогона; одни модульные тесты его не заменяют.

## English summary

A version-bounded local navigation hotfix that preserves original draft attachment ownership and the recorded preset of a reused blank chat. It does not persist browser Files across page reloads. It uses the existing session, input, upload and draft persistence owners rather than copying data or rendering hidden composers. Explicit mode requests, normal error reporting and missing-preset fallback remain intact.
